# HyperFrames 时间线视频规范 (Video Composition Spec) v1.0

> **用途**：调用 `remotion-video` skill 生成「讲解 / 教程 / 产品演示」类口播视频时，本文件是**强制约束**。
> **使用方式**：在提示词中加入一句 ——「**严格遵循 `Design/HyperFrames_视频规范.md`**」。skill 应在出 Scene Plan 之前先读本文件。
> **冲突解决**：当本规范与 `remotion-video` skill 的默认模板冲突时（最典型：进度条），**以本规范为准**。

---

## 0. 一句话原则

> **信号-响应，而非翻页。**
> 口播里每一个有意义的「信号」（关键词 / 停顿 / 转折），都必须在画面上触发一次明确的视觉响应。
> 像乐器跟着乐谱走，每个拍子都有动作 —— 不是幻灯片一张张翻。

---

## 1. 范围与不变量

| 类别 | 内容 |
|---|---|
| **适用** | 口播驱动的讲解 / 教程 / 产品演示类视频（含 AI 配音） |
| **必须保留** | 文案、配音（TTS）、素材、整体风格、配色语义、品牌元素 |
| **允许改动** | 时间编排、视觉对象、布局、动作、转场 |
| **配套偏好** | 运动须**缓慢、近乎静止**，禁止快移（船不能像公路汽车），匹配静谧氛围。动作要丰富，但每个动作的速度曲线要慢、要稳。 |

> 即：这是「重新动效 / 重新编排」，不是重做内容。文案与配音是定海神针。

## 2. 反模式清单（最高优先级 · 禁止）

先读这一节。命中任何一条 = 不合格，必须返工。

| # | 反模式 | 典型表现 | 为什么错 |
|---|---|---|---|
| A1 | **PPT 翻页式** | 一段音频 = 一整页静态画面，翻页即全部变化 | 单调、像幻灯片、信息密度低 |
| A2 | **先全页后等播完** | 整页元素一次性全显示，然后静止等音频播完 | 观众无处落眼，失去节奏 |
| A3 | **概念写成大字** | "浏览器""API""模型"只放一个加粗大词 | 偷懒，没有把抽象翻译成视觉对象 |
| A4 | **进度条** | 底部一条 `width: x%` 的进度条 | skill 默认模板自带，**本规范明确禁止** |
| A5 | **无意义英文小字** | 画面角落散落 `frame`、`step`、调试变量、占位 lorem | 视觉噪音，不传递信息 |
| A6 | **开头黑屏 / 空屏** | 第 0 帧是纯色空画面 | 第一眼就掉观众 |
| A7 | **构图僵死** | 「左大字 + 右卡片」从头到尾不变 | 违反节奏闸（见 §5） |
| A8 | **快移 / 抖动** | 元素高速飞过、相机持续微抖 | 违反「运动须缓慢」偏好；相机抖动见 skill「3D 陷阱1」 |

## 3. beat-map：时间线拆解规则

### 3.1 拆分单位
把口播按以下粒度拆成「拍子 (beat)」：**句子 → 关键词 → 停顿点**。每个 beat = 一条时间线事件。

### 3.2 关键词 = 触发器
**关键词出现的时刻，画面必须有对应变化。** 若关键词已念出而画面无响应，即违规。

### 3.3 响应类型（7 种语义类别）
关键词触发时，画面"发生哪一类事"，从下表选（可与 §9 的动作手法组合）：

| 响应类型 | 含义 |
|---|---|
| `出现` | 新视觉对象入场 |
| `移动` | 对象位移到新位置 |
| `放大` | 对象 / 视区放大聚焦 |
| `高亮` | 对象变色 / 描边 / 发光 |
| `连线` | 对象之间画路径连接 |
| `状态变化` | pending→done、灰→彩、空→满 |
| `退出` | 旧对象离场或被替代 |

### 3.4 与 Remotion 的映射
每个 beat 对应一个由 `useCurrentFrame()` 驱动的时间窗口；推荐用 `interpolate()` / `spring()` 在窗口内做动效，而非整段 `Sequence` 装一整页（避免 A1/A2）。

## 4. 抽象 → 具象 映射表

把概念翻译成视觉对象，**不要写大字**。

| 口播概念 | 视觉对象 |
|---|---|
| Codex / ChatGPT / Chrome / HyperFrames 等工具名 | **logo / 图标**（优先真实 logo） |
| 浏览器 | 浏览器窗口框（地址栏 + 标签页图形） |
| 文件 / 代码 | 文件卡片 / 代码窗口（带语法高亮块） |
| 终端 | 终端窗口（提示符 + 命令行） |
| PPT / 幻灯片 | 幻灯片缩略图卡片 |
| API | 端点节点 + 请求/响应箭头 |
| 模型 / AI | 节点网络 / 大脑图标 / 芯片图标 |
| 任务流 / 流程 | 路径图 / 流程节点 + 连线 |
| 数据 / 数值 | 具体数字标签（数值具象化，参考 skill 3B1B 风格） |

> 颜色要带语义（正=蓝/绿、负=红、高亮=黄、结果=绿、中性=灰），沿用 skill 已有配色方案，不要随意配色。

## 5. 节奏三道闸（防单调的硬性下限）

三个维度同时设下限，缺一不可：

| 维度 | 下限 | 检查方式 |
|---|---|---|
| **时间闸** | 每 **8–12 秒**画面**结构**变化一次（不是小动效，是布局/主体切换） | 抽帧看构图骨架 |
| **空间闸** | 每个章节 ≥ **3 种**不同布局（见 §6 词汇表） | 统计 layoutPreset 种类 |
| **动作闸** | 每个章节 ≥ **5 种**不同动作机制（见 §9 词汇表） | 统计 motionRecipe 种类 |

---

## 6. 布局词汇表 `layoutPreset`（空间长什么样）

| 名称 | 画面语义 | 适用场景 |
|---|---|---|
| `center-impact` | 单核心元素居中、放大冲击 | 强调一个关键概念 |
| `icon-orbit` | 多图标围绕中心排布 / 缓慢旋转 | 列举多个工具 / 环节 |
| `workspace-board` | 多窗口 / 多卡片工作台 | 环境 / 集成 / 全景 |
| `route-map` | 路径 / 流程图 | 步骤、因果、链路 |
| `zoom-lens` | 局部放大聚焦 | 挖细节、看局部 |
| `result-build` | 一步步搭出成品 | 展示产出、构建过程 |
| `node-network` | 节点 + 连线网络 | 关系、系统、数据流 |

---

## 7. 动作词汇表 `motionRecipe`（元素怎么动）

| 名称 | 手法 | 实现提示 |
|---|---|---|
| `关键词撞入` | 文字 / 元素从外冲入到位 | `spring` + 初始位移，**速度要慢**（低 stiffness） |
| `红框锁定` | 红框圈住目标元素 | 描边矩形 + 脉冲（参考 skill FocusBox） |
| `路径连线` | 节点之间画路径 | SVG path + `interpolate` stroke-dashoffset |
| `节点点亮` | 节点从暗变亮 | 颜色 / emissive 渐变 |
| `pending→done` | 状态翻转 | 灰→彩 + 勾选标记 |
| `局部放大` | 视区推近 | 相机 z 推近（**直接 set，勿插值抖动**） |
| `卡片吸附` | 卡片磁吸对齐到网格位 | `spring` 到目标坐标 |
| `旧元素被新元素推开` | 新元素入场把旧元素挤到旁位 | 物理推挤关系（**打破 PPT 感的关键手法**） |

> 所有手法的速度曲线都要**慢、稳**，禁止快移（呼应 §1 配套偏好）。

## 9. 实现映射（HyperFrames + Remotion + GSAP 注意）

**HyperFrames** 是本规范定义的**编排理念**：帧驱动的时间线，每个 beat 是一个时间窗口，由关键词触发视觉响应。落地用 Remotion 原语：

| 规范概念 | Remotion 实现 |
|---|---|
| beat 时间窗口 | `useCurrentFrame()` + `interpolate(frame, [start, end], …)` |
| 物理入场 / 吸附 | `spring({ frame: frame - delay, fps, … })` |
| 元素依次出现 | skill 已有 `StaggeredGroup`（带 `delayPerItem`） |
| 红框锁定 | skill 已有 `FocusBox`（脉冲高亮框） |
| 路径连线 | SVG `path` + `stroke-dashoffset` 由 `interpolate` 驱动 |
| 局部放大 | 相机位置**直接 set**（勿用 `+= delta*factor`，会持续抖动） |
| 进度条 | **删除**（skill 默认模板有，本规范禁止） |

**GSAP 注意事项**：
- Remotion 渲染是**逐帧独立**的，GSAP 自带 ticker 基于真实时间，直接用会导致渲染帧不精确、回放与渲染不一致。
- 若要用 GSAP，**只用它的缓动函数**（如 `Power2.easeOut`）作为 `interpolate` 的 `easing` 参数，**不要**依赖 `gsap.to()` 的内部时钟。
- 复杂时间线优先用 `interpolate` + `spring` 组合，帧精确且可回放。

## 10. 渲染与抽帧验收 Checklist

渲染 MP4 后，按关键时间点抽帧，逐项打勾。**全部 ✓ 才算合格**：

- [ ] **开头不黑屏 / 不空屏**：第 0 帧已有可见主体（A6）
- [ ] **关键词准时响应**：每个 keyword 出现的时刻，对应元素已入场 / 已变化（§3.2）
- [ ] **无无意义英文小字**：画面无 `frame`/`step`/调试变量/占位文（A5）
- [ ] **无进度条**：底部无 `width:x%` 条（A4）
- [ ] **不像 PPT 翻页**：没有「整页静止 → 翻页」的节奏（A1/A2）
- [ ] **概念不是大字**：工具名是 logo，概念是图标 / 窗口 / 节点（A3/§4）
- [ ] **节奏闸达标**：8–12s 结构变化、章节 ≥3 布局、≥5 动作（§5）
- [ ] **运动缓慢**：无快移、无相机抖动（A8/§1）
- [ ] **配色有语义**：颜色对应正/负/高亮/结果，非随意装饰
- [ ] **memoryFrame 成立**：每拍都有一个能被记住的定格画面
